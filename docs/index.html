v0.01 beta development

SHELLOOP

A terminal-only real-time step sequencer and playable synthesizer for Windows and Linux. Play it from the computer keyboard or MIDI, run deterministic patterns, and record the protected master output directly to WAV.

GitHub repository Full Windows setup Current development PR

Windows: first sound

Install Git, Rust, and Visual Studio 2022 Build Tools with Desktop development with C++, then run this from PowerShell:

git clone https://github.com/djshellshoxxx/shelloop.git
cd shelloop
git switch continuation/rebuild-baseline
cargo build --release --features realtime-audio,midi,terminal-ui
.\target\release\shelloop.exe --list-devices
.\target\release\shelloop.exe --no-midi --pattern .\patterns\example-bassline.json --bpm 138

If the intended audio output is not the Windows default, copy its exact name from --list-devices and pass --audio-device "DEVICE NAME".

Play it

Computer keyboard

Z S X D C V G B H N J Mlower note row Q 2 W 3 E R 5 T 6 Y 7 Uupper note row [ / ]octave down / up !panic / all notes off ~ or Escquit

Sequencer

Spaceplay / pause Backspacerestart pattern --bpm 138tempo --steps-per-beat 4grid density

Record a demo

This records the mono master at the selected device's actual sample rate as a 32-bit float WAV. File writing is handled off the audio callback.

.\target\release\shelloop.exe --no-midi --pattern .\patterns\example-bassline.json --bpm 138 --record .\shelloop-demo.wav

Quit normally with Esc or ~. Shelloop prints the number of frames written and any dropped or rejected recording blocks.

MIDI

.\target\release\shelloop.exe --list-devices
.\target\release\shelloop.exe --audio-device "YOUR AUDIO DEVICE" --midi-name "YOUR MIDI PORT" --polyphony 24

Note on/off, chords, sustain, panic, and MIDI reconnect handling are part of the current beta path.

Experimental PC-speaker probe

.\target\release\shelloop.exe --pc-speaker-test
.\target\release\shelloop.exe --pc-speaker-test --pc-speaker-frequency 880 --pc-speaker-duration 300

Windows: this uses the Win32 Beep compatibility API. Modern Windows normally sends that sound through the default audio device, not the physical motherboard speaker. Linux attempts the console PC-speaker ioctl and therefore needs compatible hardware and console-device permission.

What to verify

Audio

Notes respond immediately, pattern timing stays stable, and no stuck notes remain after panic or exit.

Recording

The WAV opens normally, contains the performance, and reports zero dropped/rejected blocks under ordinary load.

MIDI

Chords, sustain, note releases, and disconnect/reconnect behave cleanly.

Shelloop is currently beta-stage software. Automated Windows/Linux CI checks compile, test, lint, and build the runtime; physical audio-interface, MIDI-controller, latency, and motherboard-speaker behavior still require real hardware testing.
